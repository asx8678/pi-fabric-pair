## M1-A exact interface

`mailbox-enqueued` retains its existing metadata plus optional intrinsic `envelope:MailboxEnvelopeV2`. Omission remains intrinsically parseable but aggregate replay rejects with `unsupported-mailbox`; content is never synthesized. Aggregate requires current exact Main as recorder, matches every metadata field, full owner/endpoint/workflow binding and actual canonical UTF-8 length. Both participant and Main recipient mailboxes are represented (`targetRole` adds `main`). Delivery fields on initial enqueue must all be null; delivery facts come from later events, not preloaded receipts.

Add only private-module `validateMailboxEnvelopeV2InContext(value, context)` (mandatory registered context checked before access), reusing the public leaf's actual predicates. No facade/config/runtime tool export. Inline content pays its real capture/encoding/work cost; real payload references keep their existing charges.

Logical dedup scope is domain + full epoch + producer + consumer + idempotency key. A retry must also match the entire original envelope and metadata, not only a payload hash. Message IDs and disposition observation IDs cannot alias another message. Exact retries are no-append noops, including known prior-segment content under the same owner; unseen foreign epochs reject. Retained entries survive release.

Only Main records dispositions. Repeated dispositions must match their complete original payload, outer observation timestamp and owner. A retry retains the original observation time rather than stamping a new receipt time. First consumed/unknown service must select the replay-derived next message: ready control first; otherwise at most two question/answer messages before an available normal message. Terminal rejection/not-sent may remove an out-of-order message without claiming service. Service history changes once, survives replay/rotation and is returned in the checked view. Unknown stays occupied and cannot be converted to terminal without the future M1-B proof.

## A1-A support boundary

Only quiescent rotation is supported: no occupied mailbox, reserved activation/kernel effect, unresolved workflow or unknown usage. Sticky lifecycle/hold/history state is carried, not cleared. Checkpoint actor bindings equal actual retained Main/participant bindings, including the empty case; no invented participant identity. Counters are cumulative over the carried state, never summed twice. Unknown accounting cannot be represented by an apparently known cumulative zero.

Configuration, actor definitions and held-legacy carrier identities must remain unchanged across a segment boundary; changes need their own future explicit protocol. Old event IDs remain unavailable in the new segment. Current-segment producer authority still needs current-segment supplied authority/prefix; cross-segment activation proof consumption stays explicitly unsupported. Retained raw archive inputs are unchanged. Archive validation is semantic consistency, not Host publication provenance or permission to delete files.
